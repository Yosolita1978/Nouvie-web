### 6. Print/PDF Styles

**File modified:** `app/globals.css`

Added extensive `@media print` CSS for A4 landscape PDF output:

- `@page { size: A4 landscape; margin: 8mm 10mm; }` — page setup
- Header, footer, and `.no-print` elements hidden
- `print-color-adjust: exact` — forces background colors to render
- `.catalog-cover` — full-page cover with page break after
- `.catalog-section { break-before: page; }` — each section (Hogar, Capilar, Institucional) starts on a new page
- `.catalog-page-break` — additional class for sub-sections needing their own page (e.g., Productos Individuales)
- `.catalog-product-card { break-inside: avoid; }` — prevents cards from splitting across pages
- Compact grid, image box, and card styles for tight print layout
- Section banners compressed for print

**Important note:** Print page breaks work correctly in **Chrome**. Safari may render differently.

## Session 2026-02-17 (continued) — Fix 500 Error on Product Detail Pages

### Context

All product detail pages (`/[locale]/productos/[slug]`) were returning a 500 error in production with `DYNAMIC_SERVER_USAGE` digest. This affected every product in both Spanish and English (e.g., `/en/products/limpia-vidrios-acero-institucional`, `/es/productos/desengrasante-multiusos-concentrado`).

---

### Root Cause

The page had `generateStaticParams()` which told Next.js 16 to pre-render it as **static HTML (SSG)**. However, the page also used dynamic server functions that read from the request:

1. **`getLocale()`** from `next-intl` — reads locale from the request headers/cookies
2. **`getTranslations()`** from `next-intl` — depends on locale from the request
3. **`getProductBySlugFromDb()`** — async Prisma database call

Next.js 16 detected the conflict: a page marked for static generation cannot use dynamic server functions at runtime. This caused the `DYNAMIC_SERVER_USAGE` error on every product detail page visit.

The `/[locale]/productos` listing page (without `generateStaticParams`) worked fine because Next.js rendered it dynamically by default.

---

### Fix Applied

**File modified:** `app/[locale]/productos/[slug]/page.tsx`

| Change | Before | After |
|--------|--------|-------|
| Rendering mode | `generateStaticParams()` → SSG (●) | `export const dynamic = 'force-dynamic'` → Dynamic (ƒ) |
| `generateStaticParams()` | Present (returned all product slugs) | Removed |
| `getAllProducts` import | Used by `generateStaticParams` | Removed (unused) |

**Lines changed:** 3 (1 added, 7 removed)
